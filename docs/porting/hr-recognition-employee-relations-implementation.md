# HR Recognition and Employee Relations

## Scope and Flutter behavior

This slice ports the Flutter `AwardsRecognitionPage`, `PerformanceLeaderboardPage`, and `DisciplinaryProcessPage` at `/hr/awards-recognition`, `/hr/performance-leaderboard`, and `/hr/disciplinary-process`.

- Awards shows recent awards and a filterable award history. Flutter supports create, detail, edit, and delete. The current award schema has title, category, date, rank/level, and description; it has no recipient/employee field, so the React UI must not imply an award is linked to a person.
- The performance leaderboard is read-only. Month and year select the reporting period; the Flutter page highlights ranks 1–3 and summarizes the API response.
- Disciplinary Process lists cases with a search box and opens case details; Flutter supports create, edit, and delete. The API schema is authoritative where Flutter's form/model drifted: `date_of_violation` is required, `violation_type` is not an API field, categories/actions must use the backend model choices, and employee references are numeric employee-record IDs.

## Backend contract and limits

All endpoints are in `/api/v1` and use the shared bearer-authenticated client.

| Route              | Backend contract                                                                                                                                                                                                                                                                                                                                         | Port behavior and limits                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Awards             | `/awards/` GET (limit/offset, optional year), POST; `/awards/{id}` GET/PUT/DELETE. Permissions: awards `list`, `view`, `create`, `update`, `delete`.                                                                                                                                                                                                     | The list schema is paginated and has no search/month filter. React fetches supported pages for a year and applies text/month filtering locally. Award has no employee or branch relationship; it is an organisation-wide record.                                                                                                                                                                                                                    |
| Leaderboard        | `/monthly-scorecards/leaderboard?month=&year=` GET. Permission: monthly_scorecards `list`. The response contains at most 10 ranked scorecards, with score, rank, employee ID, and best-effort employee name/branch; `award` is currently `null`. `total_participants` and `avg_score` cover all scorecards in the caller's branch scope for that period. | Month/year remain shareable URL state. The view distinguishes the top-ten display from the all-participant summary, avoids inventing award data, and uses an employee-ID fallback when enrichment is unavailable. There is no pagination endpoint.                                                                                                                                                                                                  |
| Disciplinary cases | `/disciplinary-cases/` GET (limit/offset, optional employee_id/action_type/violation_category), POST; `/{id}` GET/PUT/DELETE. Permissions: disciplinary_cases `list`/`list_own`, `view`/`view_own`, `create`, `update`, `delete`.                                                                                                                        | React follows the exact backend action/category/date fields, uses employee choices only when `employees:list` is separately granted, and otherwise asks for a numeric employee record ID. Search is local over the loaded, permission-scoped result set because this endpoint has no free-text parameter. Backend list/detail/create/update/delete now enforce branch and department scope where available, and create/update run model validation. |

The leaderboard and disciplinary mutation paths originally failed to consistently enforce branch scope. This slice adds scoped reads/writes and regression coverage, and fixes leaderboard aggregates that previously summarized only the displayed top ten. Awards are intentionally global because the model contains no employee/branch relation.

## Route state and permissions

- Awards: URL stores `search`, `year`, `month`, `page`, `pageSize`, and optional `award_id` for a direct detail link. The route requires `awards:list`; create/edit/delete/view controls require their matching action independently.
- Leaderboard: URL stores `month` and `year`; route requires `monthly_scorecards:list` (also the sidebar resource).
- Disciplinary: URL stores `search`, action/category filters, page/pageSize, and optional `case_id`. Route allows `disciplinary_cases:list` or `list_own`; create/edit/delete require the corresponding broad permission. List-own rows remain API-owned and are never widened client-side.

## Data lifecycle

| Query                              | Freshness and scope                                                                                                                                  | Invalidation / presentation                                                                                                                                                                              |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Awards pages                       | `history` (120s); user and year scoped. Revalidate on stale route entry, focus, and reconnect; no polling.                                           | Create/update/delete invalidate the award collection. Keep cached rows during background refresh; initial failure has a local retry; distinguish true empty from filtered empty.                         |
| Monthly leaderboard                | `history` (120s); user, month, year, and permission scope. Revalidate on stale route entry, focus, and reconnect; no polling.                        | Read-only, no mutation invalidation. Preserve previous entries during period changes and show local loading/error/empty states.                                                                          |
| Disciplinary cases                 | `history` (120s); user, employee, action/category filters and branch/owner scope. Revalidate on stale route entry, focus, and reconnect; no polling. | Create/update/delete invalidate the case collection and the matching detail. Retain cached rows through refresh; keep the form draft after rejection; use separate first-load and filtered-empty states. |
| Employee selector (when permitted) | `reference` (300s); user and employee scope. Revalidate on stale route entry, focus, and reconnect; no polling.                                      | Read-only lookup; a lookup failure does not block the case list and falls back to numeric employee record ID entry.                                                                                      |
